## 2. Kiến Trúc Hệ Thống

```
Claude Code CLI
    │  giao tiếp qua stdin/stdout (stdio transport)
    ▼
server.py  (asyncio event loop)
    │  đẩy mọi COM operation vào thread riêng
    ▼
_run_in_com_thread()  ──  ThreadPoolExecutor (1 worker, STA thread)
    │
    ▼
handle_X(arguments, config, com_bridge)   ← tools/list_folders.py
                                          ← tools/read_email.py
                                          ← tools/search.py
                                          ← tools/compose.py
    │
    ▼
OutlookCOMBridge.method()   ← outlook_com.py
    │  mở context manager mới mỗi lần gọi
    ▼
with OutlookCOM() as outlook:   (CoInitialize → thao tác → CoUninitialize)
    │
    ▼
Outlook Desktop (COM/MAPI)
```

**Luồng xử lý một tool call (từ Claude đến Outlook):**
1. Claude gửi JSON `{"tool": "list_emails", "arguments": {...}}` qua stdin
2. `server.py` nhận, ghi audit log "bắt đầu", validate tool name
3. Dispatch đến `_run_in_com_thread()` → chạy `handle_X()` trong STA thread
4. `handle_X()` validate input qua `InputValidator`, gọi `OutlookCOMBridge`
5. `OutlookCOMBridge` mở `OutlookCOM` context, thực thi COM operation
6. Kết quả trả về là Python dict thuần (không có COM object)
7. `server.py` ghi audit log "thành công/lỗi", gửi JSON response về Claude

## 4. Các Tool MCP (6 tools đã đăng ký)

Tất cả được định nghĩa trong `server.py → _get_tool_definitions()` và dispatch trong `_dispatch_tool()`.

| Tool name | Handler | Mô tả |
|-----------|---------|--------|
| `list_folders` | `handle_list_folders` | Liệt kê thư mục trong allowlist + stats |
| `list_emails` | `handle_list_emails` | Danh sách email (metadata, không có body) |

- `search_emails` giới hạn `query` tối đa 200 ký tự, `limit` tối đa 50

## 7. Vấn Đề Còn Mở (Red-team 2026-06-24)

Các cảnh báo dưới đây **chưa được fix** và cần xử lý trong session tiếp theo.

### WARN-1 — `asyncio.get_event_loop()` cần đổi thành `asyncio.get_running_loop()`
- **Mức độ:** Low-medium (có thể gây deprecation warning trong Python 3.12+)
- **Vị trí cần kiểm tra:** `server.py` (đã dùng `get_running_loop()` đúng ở line 214), cần scan toàn bộ codebase để đảm bảo không còn chỗ nào dùng `get_event_loop()`
- **Hành động:** `grep -n "get_event_loop" *.py security/*.py tools/*.py`

### WARN-2 — Thiếu timeout cho COM operations ở tool handlers
- **Mức độ:** Medium (có thể làm server bị treo nếu Outlook không phản hồi)
- **Ngữ cảnh:** `server.py → _run_in_com_thread()` đã có `asyncio.wait_for(..., timeout=30.0)` — nhưng cần xác nhận timeout này áp dụng đúng cho mọi tool
- **Hành động:** Kiểm tra tất cả `_run_in_com_thread()` calls trong `_dispatch_tool()` đều đi qua `asyncio.wait_for`

### WARN-3 — Error response format không đồng bộ
- **Mức độ:** Low (gây khó nhất quán cho Claude khi parse kết quả)
- **Vấn đề:** `compose.py` trả về `{"status": "...", "error": "..."}` trong khi các file khác chỉ trả `{"error": "..."}`
- **Đề xuất fix:** Chuẩn hóa về một format duy nhất: `{"error": str}` cho lỗi, `{"status": "ok", ...}` cho thành công

### WARN-4 — `handle_list_folders` không validate qua InputValidator
- **Mức độ:** Low (rủi ro thấp vì chỉ đọc allowlist từ config, không nhận folder_name từ Claude)
- **Hành động tùy chọn:** Thêm validation để nhất quán với các handlers khác

### WARN-5 — `validate_search_query` không block dấu `'` và `"`
- **Mức độ:** Medium-High (DASL injection risk — tấn công qua câu truy vấn tìm kiếm)
- **Vị trí:** `security/validator.py → validate_search_query()`, `_DANGEROUS_PATTERNS` list (lines 39–50)
- **Ngữ cảnh:** `outlook_com.py → _build_search_dasl()` đã escape `'` thành `''` (line 1147), nhưng escape ở lớp COM không thay thế được block ở lớp validator
- **Fix đề xuất:** Thêm `"'"` và `'"'` vào `_DANGEROUS_PATTERNS`, hoặc dùng whitelist regex thay vì blacklist

## 9. Quyết Định Kiến Trúc Đã Được Chốt (Không Được Thay Đổi)

1. **COM threading model:** ThreadPoolExecutor 1 worker duy nhất — đây là yêu cầu của Windows COM STA, không phải tối ưu hóa. Tăng số worker sẽ gây lỗi không xác định.

2. **No auto-send:** Hàm `open_compose()` và `open_reply()` chỉ gọi `.Display()` — **TUYỆT ĐỐI KHÔNG** gọi `.Send()`. Đây là nguyên tắc bảo mật cốt lõi không thể thỏa hiệp.

3. **Fail-closed audit:** Nếu không ghi được audit log → từ chối xử lý tool call. Logic này ở `server.py` lines 550–563.

4. **COM per-call context:** Mỗi method của `OutlookCOMBridge` tự mở `with OutlookCOM() as outlook:` riêng — không dùng chung một COM connection. Điều này đảm bảo COM objects luôn được giải phóng kể cả khi có exception.

5. **IDOR prevention:** `read_email` và `reply_draft` đều verify folder chứa email thuộc allowlist SAU KHI resolve từ `entry_id` — ngăn IDOR (Insecure Direct Object Reference — truy cập trái phép qua ID).
